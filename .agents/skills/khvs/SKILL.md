# ХОВС

Используй готовую команду вместо повторного написания извлечения и генераторов. Нужны PDF подбора и XLSX с номерами систем в A, подготовленными A:D и пустыми параметрами E:AJ. Файлы по имени сначала ищи в Downloads; точный путь владельца имеет приоритет.

Из директории этого навыка:

```bash
bash scripts/run.sh doctor
bash scripts/run.sh run --pdf /absolute/source.pdf --template /absolute/template.xlsx --out /absolute/new-output
```

Повторный doctor не нужен, если runtime проверен в этой сессии. Для испытаний используй отдельный `--state /absolute/test-state`. Источники, кеш и результаты остаются вне Git. Команда сама архивно захватывает оригиналы в Olympus до разбора; дополнительный retain не требуется.

Прочитай короткий JSON результата. Полный source-text.txt и values.json не загружай в контекст без конкретного вопроса. Для исключений читай нужные записи issues.json и фрагменты. Значения, единицы, страницы и координаты сохранены в данных.

```bash
bash scripts/run.sh page /absolute/output --page 2
bash scripts/run.sh page /absolute/output --page 2 --bbox 50 250 295 410
```

Просмотри `.work/left.png`, `.work/right.png`, `.work/notes.png`. Первые два превью ограничены 35 строками; длинную таблицу дальше проверяй адресно через Spreadsheets. Координаты PDF измеряются в пунктах от верхнего левого угла.

`draft_with_assumptions` означает рабочий комплект, не инженерную приёмку. `needs_review` возвращает код 2, но файлы могут быть созданы — проверь JSON. При `needs_profile` или неподдержанном шаблоне явно обозначь предел автоматики и продолжай адресный разбор сохранённого исходника; правила NED не переносятся на SHUFT автоматически. После ошибки разбора команда page работает по сохранённому manifest.json.

Д1–Д3 сохраняют статус допущений; установочная мощность видима отдельно от T. Пустые поля не равны нулю или отсутствию оборудования. Полные независимые прогоны оставляй для назначенного испытания профиля, не повторяй их на каждом комплекте.

Верни result.xlsx, review.pdf, package.zip, число замечаний и границу проверки. Ноль модельных вызовов относится к самой команде, не к внешней работе агента. При изменении профиля или подключений прочитай [документацию интеграции](../../../docs/khvs-workflow.md).
