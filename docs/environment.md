# Рабочая среда Olympus на новом Mac

Архив переносит инструменты и процедуры. Оба выпуска предназначены для Mac Apple
Silicon. Для первой установки нужен интернет. Запустите **Install.command** двойным
щелчком; если macOS предлагает выбрать приложение, выполните `bash Install.command`
в Terminal из распакованной папки. Системный пароль вводит владелец.

## Что устанавливается

| Состав | Lite | Max |
|---|---|---|
| Python через uv, Node, Git, ripgrep, tmux, GitHub CLI | Да | Да |
| OpenSpec 1.12.0, Serena 1.7.0, Pyright 1.1.403 | Да | Да |
| Codex CLI, Claude Code; вход в свои аккаунты | Да | Да |
| Matt Pocock, OpenSpec, Olympus-development, три процедуры ECC | Да | Да |
| ffmpeg/ffprobe, yt-dlp без сторонних плагинов | Да | Да |
| Медиаразбор и ХОВС: код и устанавливаемые зависимости | Да | Да |
| Карты проектов, рабочие записи и проверка завершения | Да | Да |
| Файловая библиотека | Да | — |
| Ядро Olympus и отдельный Hindsight в Docker | — | Да |

Установщик не переносит venv, node_modules, HOME, материалы, ключи, авторизации и
настройки другого Mac. Он создаёт свои каталоги под
`~/.local/share/olympus-environments/` и настройки только внутри этой распакованной
папки. Повторный запуск допустим; отличающаяся чужая конфигурация вызывает понятный
отказ. Системные утилиты ставит Homebrew из текущих формул; OpenSpec/Serena/Pyright
закреплены в [toolchain](../config/toolchain.json) и npm lock. Обновление Olympus
не означает произвольного обновления всех сторонних инструментов до latest.

## Проверка и команды

```bash
./olympus plan
./olympus doctor
./olympus verify
./olympus tool openspec --version
./olympus tool pyright --version
./olympus project list
./olympus workspace list
```

Обёртка `./olympus` выбирает установленный Python 3.12 через uv, независимо
от старого системного Python. Для прямых Python-команд используйте тот же uv run.
`doctor` разделяет наличие инструментов, Docker и подключения аккаунтов. Наличие
исполняемого файла не доказывает авторизацию или доступность модели.

Откройте папку в Codex/Claude. Подтвердите native trust проекта. Serena подключается
из созданных `.codex/config.toml` / `.mcp.json`; интерфейс подтверждения определяет
сам агент. `.agents/skills` содержит навыки, `.claude/skills` ссылается на тот же
каталог. Пользовательские настройки агента остаются на новом компьютере.

Внешние приложения и коннекторы (Drive, Figma, Higgsfield и прочие) подключаются
в аккаунте агента. Архив не выдаёт доступ к ним и не копирует плагины из чужого
профиля. В поставке есть три самостоятельные MIT-процедуры ECC 2.2.1:
`ecc-tdd-workflow`, `ecc-verification-loop`, `ecc-coding-standards`.

## Медиа и ХОВС

```bash
./olympus extras media
./olympus tool reel --help
./olympus tool media plan /absolute/video.mp4
./olympus extras khvs
./olympus tool khvs doctor
```

Команда extras media устанавливает Antigravity CLI 1.2.7 в эту среду, если agy
отсутствует; проверяет SHA-512 официального архива. Существующий agy сохраняется.
[Вход](https://antigravity.google/docs/cli/install) выполняет владелец: первый
интерактивный запуск может открыть браузер. Установщик не запускает вход и модели.
Документация и manifest проверены 20.09.2026; дата публикации страницы не указана.
Медиа можно инвентаризировать и проверять локально до авторизации. Сторонние
ключи нужны только для явно выбранных внешних операций. Готовые подписки, квоты
и подключённые приложения не поставляются внутри архива.

## Docker в Max

Docker Desktop устанавливается, если CLI ещё отсутствует. Откройте приложение и
завершите его первый запуск. Принятие условий и запрос macOS выполняет владелец.
Затем подготовьте закреплённые образы и общедоступные модели:

```bash
./olympus runtime prepare
```

Это может занять несколько минут. Команда не запускает платные модели. Отдельный
Compose project использует новые volumes и порт `127.0.0.1:19888`. Если он занят,
при первой установке выберите `bash Install.command --port 19889`.

Доставьте `OLYMPUS_HINDSIGHT_API_KEY` из своего менеджера секретов в окружение
следующей команды; значение не вводите в аргументы или файлы:

```bash
./olympus runtime start
./olympus runtime status
python3 starter.py doctor --live
```

Для Bitwarden на новом Mac сначала настройте свой read-only машинный доступ и
доставку переменной. Имена/ID проекта автора не встроены. Runtime передаёт ключ
через stdin/FIFO; `docker inspect` не содержит ключ в Config.Env.

Для подписочной модели выполните отдельный вход в новый профиль:

```bash
./olympus runtime login
./olympus runtime enable-models
```

Второй команде также нужна доставка API key. Доступ конкретной модели проверяется
отдельным выбранным пилотом. `runtime start` всегда возвращает безопасный режим
без модельной обработки; `runtime stop` останавливает только эту установку.
Службы захвата разговоров и расписания не включаются при установке: для работы
инструментов они не требуются. Hook-preview Max включается только после выбора
источников и штатного доверия агента.

## Рабочие проекты

Общий интерфейс — `./olympus project ...` и `./olympus workspace ...`.
Карта пустая; добавляйте существующие проекты нового компьютера по
[маршруту](project-workspaces.md). Их код остаётся в выбранных каталогах. Навык
`olympus-development` использует эту карту и сохраняет проверяемые рабочие записи.
Результаты проверок сохраняются вне репозитория проекта. Файловая библиотека Lite
продолжает работать через `python3 olympus.py`; Max — через `./olympus memory`.

## Проверка разработки и новый архив

```bash
python3 scripts/test.py
python3 scripts/verify-distribution.py
python3 scripts/package-release.py --output /absolute/Olympus-release.tar.gz
```

Архив собирается только из проверенного `DISTRIBUTION.json`. Локальные настройки,
кеши и данные не попадают в него. Для обновления исходников выполните обычную
проверку Git diff, затем `git add` выбранных файлов и
`python3 scripts/refresh-distribution.py`; после этого повторите verifier и тесты.
