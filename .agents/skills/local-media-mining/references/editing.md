# Разбор монтажа

Этот профиль нужен для слоёв, типографики, анимаций, музыки, эффектов и связи звука
с картинкой. Переиспользуй исходник после capture-file и сверки хеша. Общие правила
доступа и квоты остаются в [antigravity.md](antigravity.md).

## Запуск

Из каталога навыка (используй абсолютные пути к команде и входу):

```bash
python3 scripts/editing.py run /absolute/video.mp4 --output /absolute/corpus/editing
python3 scripts/editing.py run /absolute/video.mp4 --output /absolute/corpus/editing --retry-failed
python3 scripts/editing.py run /absolute/video.mp4 --output /absolute/corpus/editing --only-pass audio
python3 scripts/editing.py build /absolute/corpus/editing/bundle-id
```

`--source-version` сохраняет ID заранее захваченного оригинала, если его предоставляет
проект. Хеш исходного файла всегда измеряется; переданный ID сам по себе не доказывает
соответствие записи хранилища. `--model` выбирает визуальный профиль Gemini, `--audio-model` — аудиопрофиль; текущий default
этого режима виден в `--help`/editing.py. Стандартный media.py default не меняется.

Первая версия ограничена одним выбранным коротким видео до 90 секунд, одной видеодорожкой
и не более одной аудиодорожки. Для длинного материала выбери фрагмент и сохрани его
происхождение/смещение. При крупном подготовленном входе runner явно останавливается;
сокращай выбранный фрагмент, не объявляя остаток просмотренным.

## Проходы и результат

До проходов проверь ресурсы исходного курса/автора по общему навыку. При наличии готовых
музыкальных файлов или SFX сначала составь их инвентарь и сравнивай найденные кандидаты
с миксом ролика. Новые загрузки из Drive и локальные ZIP имеют отдельное покрытие;
незавершённый сбор не превращается в отсутствие ресурсов. Для Kallaway пропущенная
библиотека и исправление описаны в docs/research/kallaway-resource-inventory-gap-2026-09-09.md.

Команда выполняет карту сцен, визуальный разбор и аудиопроход с контекстом визуальных IDs.
Gemini читает только media input; контекст предыдущего прохода передаётся как данные.
`--reuse-bundle /absolute/old-bundle` позволяет использовать те же проверенные визуальные проходы в новом bundle с другой аудиомоделью; флаг применяется вместе с --only-pass.

`--only-pass audio` явно переиспользует целые остальные проходы после проверки исходника, модели, контекста и native trace, даже после изменения runner; их прежние версии исполнения сохраняются. При изменении контекста зависимый проход требует нового запуска.

Структура проверяется по [editing_contract.py](../scripts/editing_contract.py).
Успешные проходы переиспользуются по хешам runner/контракта/входа/параметров; исправление
контракта закономерно даёт новый job. Повтор неизвестной/неуспешной попытки явный;
после одной новой ошибки цепочка останавливается и сохраняет partial-отчёт.

- `layers` — постоянные IDs объектов: фон, видео человека, оформление его окна,
  заголовок, субтитры, подписи графики, графика, вставки, branding/progress/CTA.
- `visual_events` — изменения объекта, время, bbox, текст и характер анимации.
- `audio_events` — речь, музыка, SFX, атмосфера, тишина или unknown.
- `links` — предложенные связи audio_event_id ↔ visual_event_id.
- `coverage` — объявленные пропуски, вычисленные разрывы карты и общая неопределённость.

Слой сохраняет ID при перемещении и возврате; неподтверждённая гарнитура остаётся null.
Позиции нормированы; неизвестное время — пара null, не нулевой интервал.
Число событий ограничено размером структурного ответа; модель должна указать пробелы,
когда детализация не помещается. Физическая декомпозиция MP4 на исходные монтажные слои
или чистые stems в этот результат не входит.

## Проверка связи со звуком

Локальные измерения используют original: PTS всех декодированных кадров, уменьшенную
яркостную разность соседних кадров, RMS/амплитуду с окном около 10 мс. Для аудиопрохода короткого видео сохраняется исходный MP4: в пилоте 09.09 WAV-путь выдумал речь на неречевом контрольном сигнале. При необходимости подготовки видео сохраняются FPS, временные задержки аудио и более качественная AAC-производная; исходные измерения выполняются отдельно. Для audio-only входа сохраняются sample rate/каналы и общая временная шкала в PCM16 WAV, но качество его восприятия моделью требует независимого контроля. Модель может обрабатывать аудио иначе — стереосвойства не подтверждаются самим фактом подачи стереофайла.

Сначала открой `review.html`, отфильтруй звук/слой/связи и прослушай/просмотри несколько
кандидатов. У первых кандидатов есть `evidence/`: кадры с индексом и PTS, фрагмент со
звуком. Границы фрагмента основаны на модельной оценке, а кадры — на original PTS.
Редкая тройка кадров служит навигацией; для уточнения быстрой анимации извлеки все кадры
интересующего интервала из original. Отсутствие SFX в ответе не доказывает тишину.

Энергетический пик общей дорожки может быть согласной речи или ударом музыки; он сам
по себе не подтверждает SFX. Разность двух модельных start_s не является измеренной
синхронизацией. Статусы модели остаются model_observation, связи — hypothesis.

Проверки сохраняй отдельно в `reviews.json` рядом с breakdown.json:

```json
{
  "source_sha256": "hash из manifest.json",
  "reviews": [{
    "event_id": "v1",
    "method": "frame_inspection",
    "status": "measured",
    "aspect": "appearance",
    "reviewer": "имя проверяющего",
    "note": "Что именно проверено; текст/музыка отдельно не подтверждаются",
    "evidence": [{"kind": "frame", "index": 241}]
  }]
}
```

Методы: frame_inspection, listening, signal_measurement. Статусы: measured, hypothesis,
unknown. `evidence` ссылается на реальные индексы `frame_pts` или `audio.bins` через
`kind=frame|audio_bin`. Для измеренного listening нужна `timing_note`, объясняющая
проверку времени. Такая запись — атрибутированная проверка, не автоматическая истина.
Поле aspect ограничивает смысл проверки: appearance, timing, mixed_signal, audible_identity или synchronization. Для measured timing обязателен corrected_interval с start_s/end_s; для synchronization — прослушивание и ссылки на обе временные шкалы. Пик общей дорожки не подтверждает audible_identity.

После build она отображается отдельно от raw и модельных событий. Для значимых точных
замеров укажи интервалы и ошибку в note, приложи нужные исходные кадры/фрагмент.

## Передача

Дай ссылки на `review.html`, `analysis.md`, `breakdown.json`; сообщи число принятых
проходов, проверенные моменты и пробелы. В partial сохрани доступный разбор, причину
остановки и следующий конкретный шаг. HTML локальный: оригинал остаётся по своему
пути, внешние скрипты/загрузки не требуются. JSON и Markdown являются данными для
дальнейшего анализа; существенный синтез регистрируй по контракту research проекта.

Структурные audio-поля perception_basis и sound_status сохраняют способ восприятия и reported observed/not_detected/unavailable для речи, музыки, SFX и атмосферы. not_detected не доказывает отсутствие. При неудачной контрольной пробе сохрани рядом quality-notes.json с source_sha256 и notes[{reviewer,status:"needs_review",note}]; build явно выделит эту границу в отчёте. Повторять одну неудачную проверку без нового основания не требуется.

Пилот 09.09.2026: текущий выбор визуала — 3.8 Flash High, звука — 3.1 Pro High после успешного описания четырёх известных неречевых участков. Это узкая проверка конкретного CLI/формата; качество музыки и каждого короткого SFX на реальном ролике подтверждается отдельно.
