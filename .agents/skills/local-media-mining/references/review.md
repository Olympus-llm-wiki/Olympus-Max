# Короткий review без субтитров

[Подготовка медиасреды](../../../../docs/media.md) описывает зависимости и запуск.
Доступ модели и качество выбранного режима проверяются на новом устройстве.

Используй для обзора авторов, коммерческого содержания, товаров, CTA и сравнения
коротких роликов. `reel review` делает одну компактную карточку на видео, с отдельными
основаниями из подписи, готового транскрипта, метаданных, картинки или звука.
Экранные субтитры не извлекаются. Конкретная надпись на упаковке или рекламная пометка
может быть доказательством товара/интеграции; это не полный OCR-проход.

## Вход и выполнение

Каталог пакета — `../../../packages/reel-analysis` относительно физического каталога
этого навыка (`local-media-mining`); сначала разреши symlink навыка. Сначала используй
существующие originals и тексты; проверь их происхождение и hash.
Манифест вне Git:

```json
{
  "schema_version": 1,
  "corpus_id": "creator-research",
  "items": [{
    "id": "reel-01",
    "path": "/absolute/original.mp4",
    "sha256": "<sha256 original>",
    "duration_s": 42.5,
    "context_path": "/absolute/context.json",
    "context_sha256": "<sha256 context>"
  }]
}
```

Context необязателен; поля `caption`, `transcript`, `metadata` — строки с сохранённым
содержанием. Дополнительное поле `source` может хранить URL/версии/хеши происхождения.
Передавай полный нужный текст в пределах размера context, не обрезай его молча.
При отсутствии контекста результат опирается на видео. Наличие машинного транскрипта
не доказывает, что исполнитель услышал аудио.
Output выбирай отдельным каталогом, который не содержит originals/context: runner
не пишет отчёты поверх входных файлов.

Из каталога пакета:

```bash
uv run --no-sync reel review plan /absolute/manifest.json --output /absolute/review --backend antigravity
uv run --no-sync reel review run /absolute/manifest.json --output /absolute/review --backend antigravity
uv run --no-sync reel review status --output /absolute/review
```

Долгий `run` — в именованном tmux. Выбор `--backend`, `--thinking`, `--workers` и
границы входа смотри в `--help`; текущий default закрепляется по сохранённым замерам.
При разрешённом сравнении настроек сохраняй тот же manifest/context/prompt. Другой
thinking требует отдельного output; намеренный повтор benchmark помечается новым trial.

## Текущий исполнитель

Используется только Antigravity с прежним scoped reader и проверкой подписочной квоты.
Рабочие defaults — Low и восемь независимых роликов. API-адаптеры и прошлые результаты
остаются историческими материалами, но не выбираются в текущем процессе.
Сравнение static/agentic требует отдельного выбранного эксперимента.

Runner проверяет JSON локально. Единственный объект
evidence без списка нормализуется в список без потери данных. Произвольный повреждённый
JSON, отсутствующие поля, пустой ответ и tool calls не становятся готовым результатом.
Tool calls из результата никогда не исполняются.

## Продолжение и чтение

`summary.json` и `report.md` дают состояние и обзор; `items/<id>/result.json` — карточку
с источниками. Полные ответы и причины — в `attempt-N`; история времени и новых вызовов
сохраняется в `executions/` и `attempt-ledger.json`.
Упоминания `@бренд` извлекаются из подписи локально и показываются отдельными ссылками,
даже если явного CTA нет; они не становятся призывами купить.

Для нового завершённого, но непригодного JSON-ответа `--format-retries 1` допускает
один автоматический повтор. Все попытки и расход остаются в журнале. Отсутствующий
terminal, сетевой timeout, отказ авторизации/квоты этим правилом не повторяются.

Повтор той же команды переиспользует целые результаты. Если готовый terminal raw можно
принять после локальной проверки, он восстанавливается без нового запроса. Уже сохранённые
failed/unknown требуют явного `--retry-failed`; автоматический форматный повтор не
перезапускает их при обычном resume. Повтор запускай для конкретной причины; не обходи
unknown новым каталогом под видом первоначальной попытки.
Новая независимая benchmark-проба допустима по разрешению владельца и имеет свой trial.

Проверь ключевые товары, рекламу и CTA по указанным источникам. `ready` означает пригодную
структуру, а не доказанную оплату, точную стенограмму или полное визуальное покрытие.
При нужде в дословной речи используй transcribe/готовый transcript; для выбранного
монтажного момента — inspect/editing. Полный OCR субтитров не добавляй к review автоматически.
