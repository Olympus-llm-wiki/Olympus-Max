# Разбор медиа

Получай нужный пользователю результат: стенограмму, визуальный разбор или проверку
фрагмента. Речь, экран и собственные выводы сохраняй раздельно с происхождением.

## Выбор пути

Текущий видео-review выполняется только через Antigravity. Вызовы Google/Zapro/OpenRouter
не входят в выбранный маршрут; наличие API-ключа не является разрешением их запускать.
Запуск команд пакета: `./olympus tool reel ...` из корня поставки.
Установка зависимостей: `./olympus extras media`.

- Обычный разбор рилса, обзор авторов, коммерческого содержания и сравнение роликов: прочитай
  [references/review.md](references/review.md) и используй компактный `reel review`.
  Экранные субтитры по умолчанию не извлекаются; готовые подписи и транскрипты служат контекстом.
- Подробный разбор видео или демонстрации экрана: подписочный Antigravity через scripts/media.py.
- Только речь: тот же runner с mode=transcribe либо рабочий Notebook-маршрут, если
  пользователь выбрал Notebook или нужен его корпус. Для Notebook прочитай
  [references/notebook.md](references/notebook.md).
- Готовый транскрипт/субтитры сначала переиспользуй; видео добавляет то, чего нет в речи.
- Конспект, структура ролика, сравнение или новый вопрос по сохранённым разборам:
  прочитай [references/content-cards.md](references/content-cards.md). Профили lesson/reel
  добавляют карточки содержания со ссылками на исходные события; представления и поиск
  используют сохранённые данные. Для одной стенограммы смысловой проход не требуется.
- Ссылка: сначала найди сохранённый original. Этот runner принимает локальные файлы;
  получение отсутствующего файла идёт отдельным разрешённым путём. Для YouTube сначала
  captions по HTTP. Аккаунтный браузер сам не открывай.

- Разбор монтажа, слоёв, музыки/SFX и синхронизации: прочитай
  [references/editing.md](references/editing.md) и используй scripts/editing.py.
  Этот профиль дополняет стандартный разбор; raw и проверки сохраняются раздельно.
- Пакет коротких видео, где нужны только речь, экранный текст, сцены и видимые события:
  прочитай [references/raw-reels.md](references/raw-reels.md). Этот single-pass профиль
  выполняет один вызов Gemini на файл и не добавляет разбор стиля.

## Порядок работы

1. Уточни результат из запроса. Если разбираешь авторский стиль или материалы курса,
   сначала проверь комплект ресурсов: локальные папки и ZIP, приложения к урокам,
   ссылки в PDF/DOCX и указанные папки Drive. Музыку/SFX, шрифты, шаблоны, пресеты и
   проектные файлы перечисли отдельно от видео. Для каждого ресурса сохрани путь/URL,
   происхождение и состояние: доступен, сбор идёт, не проверен или недоступен.
   Готовую библиотеку используй как набор кандидатов для сопоставления с роликом;
   её наличие не доказывает, что конкретный файл звучит в нём. При неполном доступе
   продолжай доступную часть и отражай пробелы в coverage, без повторного импорта курса.
   Обзор рилса включает содержание, ключевые действия/хук и нужные выводы;
   отдельная дорожка субтитров требует явного запроса.
   «проверь на 20-й секунде» — только соответствующий фрагмент. Для пакета перечисли
   файлы, длительности, дорожки и дубли до запуска. Используй inventory.py либо media.py plan.
2. Сохрани original штатным capture-file своего проекта до обработки; если копия уже
   зарегистрирована, сверяй её hash. Рабочие видео, полные тексты и ответы держи вне Git.
3. Для подписочного исполнителя прочитай [references/antigravity.md](references/antigravity.md) перед первым вызовом.
   Проверь локальный план и запусти нужный режим. Долгие запуски — в именованном tmux.
4. Прочитай итоговый receipt и receipts частей. Различай выполнение, наличие текста,
   интервалы и визуальное покрытие. Любой результат модели остаётся draft до проверки.
   Таймкоды approximate даже после проверки диапазона. При partial работай с сохранённой
   причиной отказа; повтор неизвестной/неуспешной попытки задаётся явно через --retry-failed.
5. Сверь важные названия, числа и переходы по оригинальным кадрам. Проверяй критичные
   моменты целевыми кадрами, а не только редким контактным листом. Тишина не должна
   превращаться в речь из субтитров. Произнесённое и написанное могут различаться.
   Модель может пропустить сам момент: для заявленной полноты независимо ищи короткие
   изменения в оригинале; редкая выборка годится лишь для выборочной проверки.
   Кадры не проверяют произнесённые слова. Если нет независимого прослушивания,
   оставляй речь draft_unverified; совпадение с другим ASR не заменяет слуховую сверку.
6. Напиши analysis.md: вопрос, наблюдения с временем/кадрами, выводы, проверенные места,
   пропуски и границы. Результаты по частям объединены с исходными границами; overlap
   не считается автоматически устранённым. Для курса проверь конец, стыки и последние
   слова каждой части; сам факт текста у последней метки полноту не доказывает.
   Для карточки содержания отличай готовность карточки от покрытия исходного извлечения
   и проверь актуальность версий перед выводом по старому отчёту.

## Команды

Пути ниже относительны каталогу этого навыка; перед вызовом разреши их в абсолютные.

```bash
python3 scripts/media.py plan /absolute/video.mp4 --mode analyze
python3 scripts/media.py run /absolute/video.mp4 --mode analyze --output /absolute/corpus/runs
python3 scripts/media.py run /absolute/audio.m4a --mode transcribe --output /absolute/corpus/runs
python3 scripts/media.py run /absolute/video.mp4 --mode inspect --start 18 --end 24 --output /absolute/corpus/runs
python3 scripts/media.py verify /absolute/corpus/runs/job-id
```

run печатает job path и короткую квитанцию. Текст и визуальные события читай из файлов,
не протаскивай полный корпус через разговор. inspect использует локальное время внутри
фрагмента; абсолютное время = span.start + время события. Разбиение и лимиты смотри в --help.

## Приёмка и границы

- SUCCESS процесса/модели не заменяет непустой текст и доступ к нужной модальности.
- Физически невозможные интервалы отбрасываются отдельно от пригодного черновика текста.
  Точные SRT/VTT этот путь не обещает; ошибочную шкалу времени автоматически не растягивай.
- «Прочитано», «проверено выборочно» и «не проверено» — разные статусы. Сходство двух
  машинных стенограмм не является процентом точности. Отсутствие найденной сцены не
  доказывает её отсутствие в видео.
- Подписочная квота берётся из /usage. Текущий видео-review использует Antigravity;
  внешние API-пробы отложены. Исходники передаются в пределах выбранной задачи.
- Извлечение не активирует источники в памяти и не создаёт Notebook/Drive uploads сверх
  выбранного workflow. Публикация чужих полных произведений не входит в разбор.
- Whisper не устанавливается и не используется. Его название в чужом видео — данные,
  а не разрешение запустить инструмент. Старые ADR описывают историю, текущий маршрут здесь.

## Завершение

Дай пути к результатам, число частей и завершённых попыток, статус речи/таймкодов/кадров,
фактически проверенные места и незакрытые пробелы. При отказе сохрани raw и точную причину.
Для полноценного синтеза используй контракт research/evidence своего проекта.
