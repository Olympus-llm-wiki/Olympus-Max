# Notebook: корпус и импорт речи

Используй этот путь, когда выбран Notebook или продолжается работа с его корпусом.
Это альтернативная ветка того же навыка, а не обязательный повтор после Antigravity.

1. Инвентарь исходных файлов: длительность, аудиодорожка, дубли, битые контейнеры.
2. Подготовь компактное аудио через scripts/to-audio.sh. Прежняя настройка — M4A AAC
   32k mono для Notebook; при важных отдельных каналах сохрани оригинал и явно учитывай
   потерю разделения. Пределы сервиса проверяй перед большим импортом.
3. Одна тетрадь на логический источник (курс/серия). Загружай последовательно;
   после неоднозначного отказа сначала сверь список источников, чтобы не создать дубли.
4. Получай индексированный текст источника через `nlm source content ID --output file.txt`,
   а не просьбой к чату пересказать источник. Сам текст уже результат ASR и может ошибаться.
5. Сразу сохрани текст и provenance локально. Проверь конец и подозрительные имена/числа.
   Закрытие работы/удаление облачных источников выполняй в рамках явно выбранного lifecycle.

Видео при audio import не получает гарантированного разбора кадров; YouTube URL
использует готовые captions. Стенограмма не заменяет непроговорённый экран.
Consumer-коннектор неофициален; Android backend также не является публичным Google API.
Для файла документа действуй по notebooklm-source-corpus, если он доступен.

Перед использованием MCP-download старого notebooklm-mcp-cli 0.9.14 нужно исправление
0.10.1 или более поздняя проверенная версия; зафиксируй allowed file/download directories.
Не устанавливай второй одноимённый MCP без проверки существующего executable:
notebooklm-py и notebooklm-mcp-cli могут предоставлять одинаковое имя notebooklm-mcp.
Не нажимай feedback в рабочих notebooks. Квоты и retention — по действующим условиям
выбранного consumer/Workspace/Enterprise продукта, а не по старой заметке.
