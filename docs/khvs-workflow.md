# ХОВС в Olympus

**Локальная команда переносит поддержанный текстовый подбор NED в шаблон ХОВС.**
**Извлечение кешируется; внутри команды нет обращений к модели, но сохраняются происхождение и рабочие допущения.**
**Навык запускает процесс и помогает разбирать исключения; инженерное проектирование и приёмка не выполняются.**

## Когда использовать

[Навык khvs](../.agents/skills/khvs/SKILL.md) предназначен для технического PDF NED и существующей книги характеристик отопительно-вентиляционного оборудования. Первый профиль `ned-khvs-1` распознаёт системы, приток/вытяжку, вентиляторы, водяные/электрические нагреватели, охладители и четыре ступени фильтрации. Проверены синтетические сценарии и один сохранённый регрессионный комплект; поддержка всех выпусков программы NED не заявляется.

Нужен один статический лист с шапкой A1:AJ7, уникальными системами в A, подготовленными A:D и пустой областью параметров E:AJ. Приточно-вытяжная система занимает две строки с объединённым номером. Порядок PDF и строк Excel может различаться. Назначение помещений, размещение и количество из A:D автоматически не проверяются.

SHUFT, сканы, DWG, другой шаблон, формулы, внешние ссылки, макросы, рисунки, таблицы Excel и старые комментарии требуют другого пути или расширения профиля. Отказ явный; исходники сохраняются. Наличие источника в Olympus не доказывает поддержку его формата.

## Запуск

Из корня репозитория:

```bash
bash scripts/khvs.sh doctor
bash scripts/khvs.sh profiles
bash scripts/khvs.sh run \
  --pdf ~/Downloads/project.pdf \
  --template ~/Downloads/khvs-template.xlsx \
  --out ~/Documents/Research/engineering-ai/jobs/project-001
```

Имя без пути сначала ищется в Downloads. Точный абсолютный или составной относительный путь используется как задан. Папка результата новая или пустая; входы, результат, состояние и кеш находятся вне Git. Команда работает с неизменяемыми копиями и не перезаписывает исходники.

По умолчанию используется bundled runtime Codex. doctor сообщает недостающие зависимости без установки. Для выбранной среды доступны `KHVS_PYTHON`, `KHVS_NODE`, `KHVS_NODE_MODULES`. Проверенные версии: pdfplumber 0.11.9, pypdf 6.10.0, reportlab 4.4.9, openpyxl 3.1.5 для чтения/проверки, lxml 6.1.1, Artifact Tool из runtime 26.905.11957. Ядро памяти сохраняет прежний набор обязательных зависимостей; Python-пакеты ХОВС перечислены в опциональной группе `khvs` файла pyproject.toml. Для XLSX также нужен Artifact Tool из runtime.

## Выходной комплект

| Файл | Назначение |
|---|---|
| result.xlsx | Значения, уточнённые заголовки, цветовые пометки, примечания и установочные мощности под таблицей |
| review.pdf | Проверка по системам и внутренние ссылки к копиям исходных страниц |
| values.json | Значения, единицы, страницы, области, исходные подписи, статусы и версии источников |
| issues.json | Противоречия, проблемы сопоставления и неизвлечённые поля |
| manifest.json | Снимки входов, хеши, квитанции, версии и результаты проверок |
| metrics.json | Время этапов, кеш и модельные вызовы команды; метрики остаются отдельно от архива для автора |
| package.zip | Рабочий комплект с входными копиями и данными проверки |
| .work/*.png | Превью первых 35 строк XLSX и примечаний; это не весь длинный лист |

stdout — короткий JSON. Код 0 означает созданный рабочий комплект. Код 2 и needs_review могут сопровождаться готовыми файлами. needs_profile/unsupported_template объясняют предел обработки. При сбое сохраняется failure.json; после успешного захвата manifest.json позволяет посмотреть исходник.

## Проверка исключения

```bash
bash scripts/khvs.sh page ~/Documents/Research/engineering-ai/jobs/project-001 --page 2
bash scripts/khvs.sh page ~/Documents/Research/engineering-ai/jobs/project-001 \
  --page 2 --bbox 50 250 295 410
```

Проверяется хеш снимка PDF; PNG сохраняется в evidence/. Координаты `(x0, top, x1, bottom)` — пункты от верхнего левого угла. Начинайте с конкретных замечаний и областей. Полный документ нужен при неизвестной структуре или изменении профиля, а не для каждого повторного запуска.

Другая единица или конфликт значений не получают молчаливый приоритет. Несколько однотипных компонентов/вентиляторов не агрегируются. Присутствующая, но неподдержанная секция требует разбора. Если автоматический путь не подходит, агент может продолжить работу общими PDF/Spreadsheets-инструментами, сохранив источники и явные ограничения.

## Допущения

| ID | Рабочее правило |
|---|---|
| Д1 | T — потребляемая мощность нагрева из подбора; установочная сохранена отдельно. T нельзя автоматически переносить в проект электрических нагрузок. |
| Д2 | «бак.сек.» трактуется как бактерицидная секция; AJ совмещает четвёртый фильтр и дополнение по принятому шаблону. Конкретная модель и параметры не подбираются. |
| Д3 | X — расчётная мощность охлаждения. Квалификация «полная/явная» не добавляется; значение не становится электрической мощностью ККБ. |

Серое поле означает, что характеристика не установлена автоматическим разбором. Это не ноль, не «нет» и не доказательство отсутствия устройства. F определяется распознанным профилем NED, а не проверкой юридического изготовителя. Повторное использование не превращает допущение в подтверждённый факт.

## Связь с памятью

Используется существующий Store.capture: точные входы сохраняются архивно **до разбора**, затем извлечение и результаты связываются с родительскими версиями. Идентичность входа основана на содержимом, поэтому переименование не обходит отзыв источника. Доставка в модели, старые банки, бюджет и права не включаются. Локальная квитанция не подтверждает Hindsight или удалённую копию.

Кеш по умолчанию находится в `~/.local/state/olympus/khvs/cache`; другой путь задаётся через `--cache`. Ключ включает SHA-256 PDF, версию извлечения и pdfplumber. Контрольная сумма проверяется, повреждение вызывает новое извлечение. Сопоставление и генерация выполняются заново, поэтому изменение правил не требует повторного извлечения неизменного PDF. Кеш производный и не заменяет оригинал.

## Когда подключать другие инструменты

| Ситуация | Маршрут |
|---|---|
| Несколько комплектов в неделю из Downloads | Локальная команда и навык |
| Общая папка Google Drive | Получить полные файлы штатным коннектором, затем та же команда; доступ к рабочей папке настраивается отдельно |
| Сканы или сложная вёрстка | Испытать OCR/Docling на конкретных страницах; сейчас автоматически не запускается |
| Структурированный экспорт программы подбора | Проверить схему и происхождение; такой экспорт NED пока не подтверждён |
| DWG | Проверить штатное извлечение AutoCAD для фактических версии/ОС; нужен отдельный входной профиль |
| Несколько агентов/клиентов | Обернуть эти же операции в MCP; такого подключения пока нет |

На сохранённом комплекте из 53 страниц перенесены 182 значения для 11 систем: совпали все 138 ранее проверенных по источнику контрольных значений и все 182 значения предыдущей версии. Это контрольная разметка ассистента, не инженерное утверждение. 176 полей остались неизвлечёнными; отсутствие ошибок разбора не означает полноту проектных данных.

Полный запуск с превью окончательного XLSX занял 5,43 с без кеша и 2,56 с с кешем; внутри команды 0 модельных вызовов. Проверены 204 ссылки PDF, сохранность 53 исходных страниц, значения, стили, объединения и настройки печати XLSX. Отдельный агент без истории прошёл инструкцию на двух синтетических системах с переставленными строками, без ручного исправления результата. Это проверка инструкции, а не жёсткая изоляция файловой системы.

[Машинная квитанция и версии](evidence/khvs-pilot.json) не содержит клиентских документов или параметров. Время зависит от машины и размера Store. Полный новый реальный комплект нужен для оценки переноса на незнакомые документы.

Код — [olympus.khvs](../src/olympus/khvs/), проверки — [test_khvs.py](../tests/test_khvs.py). При изменении структуры извлечения обновите её версию, чтобы старый кеш не выдавался за новый результат.

```bash
PYTHONPATH=src "$KHVS_PYTHON" -m unittest discover -s tests -p test_khvs.py -v
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

В первой команде задайте runtime из doctor. Синтетические испытания используют отдельное состояние. Реальные документы, полные результаты и золотые значения не помещаются в Git. Замеры публикуются для конкретного случая; 0 модельных вызовов относится к команде, не к её разработке или внешней работе агента. Новый реальный комплект ещё нужен для проверки обобщения.

Первичные интерфейсы: [pdfplumber 0.11.9](https://github.com/jsvine/pdfplumber/tree/v0.11.9), [pypdf 6.10.0](https://pypdf.readthedocs.io/en/6.10.0/user/adding-pdf-annotations.html), [навыки Codex](https://learn.chatgpt.com/use-cases/reusable-codex-skills). Проверка 07.09.2026; отраслевые правила остаются рабочим профилем, не нормативным заключением.
