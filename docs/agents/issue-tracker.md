# Планы и задачи навыков Matt Pocock

Трекер этого проекта — локальный OpenSpec, а не GitHub Issues или `.scratch`.
Это проектная адаптация мест публикации upstream-навыков.

- `/to-spec`: синтезировать обсуждение в `openspec/changes/<change>/proposal.md`,
  `design.md` и delta specs через существующий OpenSpec-процесс. Для существующего
  изменения обновлять его документы. Не создавать независимую копию спецификации.
- `/to-tickets`: записывать согласованные срезы с устойчивыми номерами, зависимостями
  и критериями проверки в `tasks.md` того же change. Требование upstream «один файл
  на тикет в .scratch» здесь заменено существующим форматом OpenSpec.
- `/implement`: читать этот change, выполнять задачи по зависимостям, отмечать
  завершённое по результатам проверок. Архивация следует OpenSpec-процессу.
- `/triage`: применять смысл ролей из `triage-labels.md` к явно выбранным местным
  задачам. Не создавать внешние issues, labels или сообщения автоматически.
- `/wayfinder`: карта вопросов при необходимости живёт в `discovery/map.md` внутри
  change, дочерние вопросы — в `discovery/issues/NN-slug.md`. Каждый вопрос содержит
  Type, Status, Blocked by, основание и ответ. Карта ссылается на канонические
  требования и задачи; не дублирует их. Frontier — незакрытые вопросы без открытых
  зависимостей, claim/resolution записываются в вопросе.

Готовность задачи к работе не является разрешением владельца на реализацию или
внешнее действие. Неизвестные решения остаются открытыми, а не заполняются догадками.
Эти настройки относятся только к Olympus Max; для другого репозитория сначала установить
его действующие правила и место хранения задач.
