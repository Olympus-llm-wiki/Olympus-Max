# capture-completeness Specification

## Purpose

Точно оценивать полноту разрешённого текста разговора, исключая внутренние сообщения и сохраняя видимость неизвестных пользовательских форматов.

## Requirements

### Requirement: Внутренние роли исключаются независимо от metadata

Система SHALL исключать system/developer сообщения из захвата без чтения их содержимого редактором. Неизвестные content metadata этих ролей SHALL NOT создавать пробел полноты пользовательского разговора.

#### Scenario: Служебное сообщение режима подагентов
- **WHEN** между пользовательскими сообщениями завершённого хода встречается developer message с `multi_agent.mode_instructions`
- **THEN** служебный текст не сохраняется, а разрешённый завершённый ход остаётся доступен для захвата

### Requirement: Неизвестные разрешённые сообщения остаются видимым пробелом

Система SHALL сохранять строгую проверку content metadata для разрешённых ролей и SHALL сообщать пробел для неизвестной формы вместо молчаливого подтверждения полноты.

#### Scenario: Неизвестный вид пользовательского содержимого
- **WHEN** user message содержит неизвестный content item kind
- **THEN** полнота не подтверждается и возвращается соответствующий код пробела

### Requirement: Служебные вставки исключаются поэлементно

Известные platform control kinds, включая agents_md.instructions и plugins.recommendations, SHALL исключаться без передачи их текста редактору. Обычные user.text в том же сообщении SHALL сохраняться; неизвестные виды SHALL по-прежнему создавать пробел.

#### Scenario: Смешанное сообщение
- **WHEN** один response содержит обычный пользовательский текст и служебную вставку
- **THEN** пользовательский текст сохраняется, а служебный исключается без ложного пробела
